# 可复用经验

更新日期：2026-08-24

这里只记录已经确认过的故障规律、根因和预防方法。长期产品或架构取舍见 `DECISIONS.md`。

## 构建环境

### 单文件脚本的数据替换必须一次完成

- 现象与根因：若构建器把 JSON 注入脚本后继续逐项扫描占位符，资料文字中的同名占位符会被误判；未转义的 `</script>` 还可能提前结束内联脚本。
- 预防：只在原始应用源码中检查每个占位符恰好一次，使用一次正则回调完成替换；内联 JSON 转义 `<`、`>`、`&`、U+2028 和 U+2029，并由 `web/build-template-test.js` 覆盖特殊文字。

### Windows 无法创建 winCodeSign 的 macOS 符号链接

- 现象与根因：electron-builder 解压 `winCodeSign-2.6.0.7z` 时创建 `.dylib` 符号链接失败，普通 Windows 用户没有相应权限，而这些文件只供 macOS 使用。
- 处理：由 `scripts/prepare-builder-cache.ps1` 预解压并排除 `darwin`；保留 `.cache/electron-builder/`，不要因此清空缓存。

### 过长路径会破坏 NSIS 构建

- NSIS include 路径在深层任务目录中可能失败。正式工作区固定为 `<WORKSPACE>`，不要再次嵌套到日期或任务目录。

### 构建工具升级必须先隔离验证

- 较新 electron-builder 曾引入当前网络无法通过 GitHub SSH 获取的依赖。现阶段锁定 electron-builder `24.13.3` 和 Electron `31.7.7`，升级时先在独立分支验证。
- Electron 和 builder 二进制使用 `scripts/common.ps1` 配置的国内镜像，避免各脚本重复定义下载地址。

### Windows PowerShell 脚本保持 ASCII

- Windows PowerShell 5 读取 UTF-8 无 BOM 的中文 `.ps1` 可能乱码并破坏语法。自动化脚本保持 ASCII，中文说明放 Markdown；确需中文脚本时明确使用兼容编码。
- PowerShell 双引号中若变量后紧跟冒号，写 `${file}:` 而不是 `$file:`，否则解析器会把它当成非法 drive-qualified variable。安装脚本收尾同时做 AST parse 和非 ASCII byte 检查。

### Node、pnpm 与缓存错误先查路径和权限

- Codex 自带 Node 不一定在系统 PATH；`scripts/common.ps1` 会定位 Node/pnpm 并为当前进程补 PATH，无需依赖用户全局环境。
- pnpm 报 `unable to open database file` 时，先核对 `.pnpm-store/v11/index.db`、目录权限和执行环境。数据库存在但不可写不代表缓存损坏，不要先删除缓存或重装依赖。

## 自动化与桌面测试

### 调试端口可用不等于页面已经就绪

- CDP `/json` 出现后页面 DOM 仍可能为空。烟雾测试必须等待标题和设备选项出现，再执行断言。

### 模态框和文件导入会影响焦点

- 前一个用例留下打开的模态框时，浏览器会阻止搜索框获取焦点。焦点用例使用隔离用户目录和全新进程，或先显式关闭全部模态框。
- Electron 文件选择框与同步提示连续关闭后，WebContents 可能不再接收键盘输入。导入收尾要通过受限 IPC 聚焦 BrowserWindow/WebContents，再聚焦搜索框；测试同时断言真实 `File` 导入、搜索和立即编辑。

### 持久化测试必须正常关闭应用

- `taskkill /F` 可能发生在 Chromium 刷写 localStorage 之前。持久化验证使用正常关闭，只把强制结束作为清理后备。

### 网页通过不代表打包版输入通过

- 打包版输入异常应直接启动对应文件夹产物，用真实点击和键盘验证标签、连接器、备注和搜索。复现前先确认选中的是可编辑 GPIO，固定电源脚本来不可编辑。

### 引脚计数和 portable 启动需要专用判定

- `aria-label^="Pin 1"` 也会命中芯片方向标记；引脚计数应限定 `button[aria-label^="Pin "]`，并断言首末物理脚。
- 文件夹版可直接传递远程调试参数，portable 的 NSIS 启动器不一定透传。正式 portable 验收要准备直接窗口控制，核对窗口标题、版本、输入和正常关闭，而不是只看进程存在。

## 搜索、数据与迁移

### 结构化 GPIO 查询必须完整匹配

- `PB1` 不能命中 `PB10/PB11/PB12`。PA/PB 查询按字母数字 token 完整匹配；外设关键词、板卡说明、标签和备注才使用包含匹配。
- 自定义标签命中只代表实际含该标签的已编辑引脚；`编码器/QEI/TIMER` 等功能别名可以扩展外设候选，但不能伪造标签匹配。

### 新工程默认值不能进入已保存工程规范化

- 新建工程可以预置官方或板卡默认功能，加载、导入、复制和清空必须以保存内容为准。否则软件会悄悄改写用户规划。
- 回归至少覆盖全新工程、当前工作区/JSON 往返、修改后重启和清空；相同物理用途也要尊重芯片差异，例如 NRST/WAKE 只存在于官方支持的芯片。

### 工程目标应在创建时固定

- 一个工程同时保存全部芯片和封装，会让型号切换看起来像修改同一设计，容易误把不同硬件目标混在一起。
- 工程数据只保存一个 `device/package`，模板在创建时固定目标；不同型号或封装应新建工程。型号和封装已经在芯片画布中显示时，顶部不再重复放只读或可编辑控件。

### 相同封装或脚位不代表能跨芯片复用功能

- RGZ-48 与 PT-48 仅因同一芯片官方表确认一致才可复用。MSPM0G3507 与 MSPM0G3519 的 RHB-32 虽物理脚序相同，IOMUX 集合仍不同，必须按逻辑引脚回查同一芯片数据。
- 数据生成器应保持既有 JSON 顺序并追加封装，避免内容正确但产生大范围无意义 diff。

### PCB 模块端子必须换算到 MCU 物理脚

- EDA 网表中的核心板模块端子号不是 MCU 物理脚号。转换顺序应为“模块端子 -> PA/PB -> 目标芯片封装物理脚”。
- 网络名只有出现在目标 GPIO 官方功能列表中时才能自动选择复用功能；用途名、软件 I2C 或普通中断保留为 GPIO 标签。
- Telesis 网表可能缺少图形层上的 UART、定时器和模块用途，需要同时核对原生工程、PDF、器件引脚名和官方 IOMUX；推断应保留依据，不把猜测写成官方事实。

## 界面布局

### 桌面布局要覆盖最小目标宽度

- 顶部工具栏在 1440 px 正常不代表 1100/1300 px 正常。桌面验收至少检查 1100、1300、1440 px，并保证品牌、选择器和操作按钮不会被推出视口。

### 旋转标签按实际长度预留轨道

- 上下边标签旋转 90 度后，原始宽度成为垂直占用长度。标签轨道要有稳定高度并从引脚格向外延伸；测试应量取边界、间距和容器包含关系。
- 旋转方向和锚点必须成对设计：底边若使用 `rotate(-90deg)` 形成向左歪头阅读的方向，应把锚点放在外侧轨道末端，使文字向上延伸到引脚下方；只改旋转方向而不移动锚点会让文字穿过引脚格。
- 旋转容器的边界贴近引脚不代表短文字也贴近；使用末端锚点时还要把容器内文本对齐到靠引脚的一端，并用实际文字范围而非容器范围检查视觉间距。

### 临时画布适配必须先接管用户交互

- 分栏开合若使用不落盘的临时缩放/位移，滚轮和拖动不能继续从持久视图读取起点；否则第一次缩放或平移会跳回旧坐标。用户开始操作时应先把当前临时显示提升为正式视图，再计算缩放锚点或拖动起点，并取消仍在等待的自动重排帧。

### 离线 HTML 的视觉结果以真实截图为准

- 内置浏览器可能因安全策略拒绝 `file://`，这不是项目构建失败。自动预览受阻时停止重复等待，交付离线 HTML 并请用户提供实际截图定位错位。

## 导出安全

### CSV 引号不能单独阻止公式识别

- 现象与根因：部分表格软件仍会把带 CSV 引号但内容以 `=、+、-、@` 开头的单元格当作公式，前置空格、Tab 或隐藏空白也可能绕过简单的首字符判断。
- 预防：只在 CSV 输出层给这类单元格添加文本标记并强制加引号；不要改写工程或 JSON 中的原始用户文字。所有 CSV 导出必须共用 `csvEscape()` 并由危险文字回归检查覆盖。

## 板卡模板

### 板级限制与官方芯片能力分层

- 晶振占用、未引出、排针编号和板载上拉属于 PCB，不能改写官方 IOMUX，也不能塞进可被用户覆盖的备注。
- 共用板级走线不等于共用芯片功能表；每颗芯片的模板默认功能都要独立校验。

### 一个引脚必须能表达多条板载连接

- SPI 多个从设备可以共享数据线和时钟，只要片选独立。单个 `label/detail` 会让后录入资源覆盖先前信息，应使用 `resources` 保存每条连接，并用 `sharedBuses` 说明共享线与独立片选。
- 封装图、搜索、检查器、冲突检查和导出必须读取同一关系，避免不同界面各自丢失一部分板载资源。

### 关闭板卡资源不能删除用户文字

- 现象与根因：功能、标签、连接器和备注保存在同一条引脚安排中；直接删除资源预设功能对应的整条安排，会连同用户文字一起丢失。
- 预防：关闭资源时只清空仍等于预设值的 `function`，再用 `isMeaningfulAssignment()` 判断是否保留记录；共享总线应等最后一个使用者关闭后再释放功能。

### 嵌套模板字符串会破坏烟雾脚本语法

- 现象与根因：桌面烟雾测试的大段浏览器表达式本身使用模板字符串；在表达式内直接加入反引号 CSS 选择器会让 Node 在执行前报 `Unexpected identifier`。
- 预防：嵌入选择器和动态文本优先使用普通字符串拼接，修改后先运行 `node --check desktop/scripts/smoke-test.js`。

### 画布上方控制面板不应挤压封装布局

- 现象与根因：把可展开板卡信息作为普通文档流区域放在画布前，会在展开时减少画布高度，导致封装和引脚备注整体下移。
- 预防：工具栏内的板卡控制使用相对定位容器和绝对定位浮层，封装画布保持原有尺寸。浮层仍受中心区域的 `overflow: hidden` 约束，不能用跨出中心区的大宽度；资源较多时使用窄幅单列滚动布局。
