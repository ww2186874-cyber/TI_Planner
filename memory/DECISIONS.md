# 长期决策

这里只记录仍然有效的产品、架构和工作流取舍。当前版本和待办见 `PROJECT_STATE.md` 与 `SESSION_HANDOFF.md`。

## 产品与平台（2026-07-14，2026-08-24 更新）

- 本仓库只维护网页/Electron 主产品；DeepSeek Harness 插件使用用户 Web Profile 内的独立 Git 仓库，两个仓库不采用子模块或隐式路径依赖。
- 交付目标为 Windows x64 Electron 桌面应用，优先保证目标电脑无需安装 Node、WebView2 或额外运行库；暂不以手机、macOS、Linux 或 32 位 Windows 为验收目标。
- 网页/Electron 主产品只做引脚规划，不生成初始化代码。
- 用户数据保存在当前电脑，不随 U 盘移动；文件夹版必须整体复制，单文件便携版允许启动时解压较慢。
- 品牌使用原创无厂商文字的芯片图形，并明确“非 TI 官方工具”。作者统一为“天津职业技术师范大学 电子创新协会”。发布物保留项目许可证、第三方声明和数据来源。
- QEI 完整性只要求 C0/A 相和 C1/B 相，IDX/Z 索引保持可选。

## 公开仓库与隐私边界（2026-08-28）

- 主产品 GitHub 仓库公开可见，但授权范围仍以 `legal/LICENSE.md` 为准；公开不等于采用通用开源许可证。
- 公开历史不得包含本机用户名、绝对路径、私有备份、凭据或独立 Harness 插件源码。插件只保留仓库边界说明，源码继续由独立仓库维护。
- 历史改写前备份只在仓库外私有保存，不得上传到公开仓库、Release、Actions artifact 或其他公开位置。

## 候选与正式发布（2026-07-14，2026-08-28 更新）

- `outputs/` 是可覆盖候选区，`releases/vX.Y.Z/` 是不可覆盖正式归档；Git 记录源码、文档、release notes 和哈希清单，不记录大型生成物与依赖缓存。
- 默认所有修改只生成网页版 HTML 供确认；HTML 确认本身不会触发文件夹版、便携 EXE 或 Electron 打包。
- 只有用户明确说“发布”后，才一次性构建文件夹版、便携 EXE 并创建正式归档。
- beta 候选可以提交 Git，但不创建正式标签。正式版本同时归档离线 HTML、文件夹版和便携 EXE，验证后创建对应标签。
- 标签前验收失败的构建不可覆盖或打标签；若保留在版本目录中用于审计，必须添加 `REJECTED.md` 和禁止分发说明，再提升版本发布。只有无拒绝标记且有同名 Git 标签的归档才是正式版本。
- `create-release.cmd` 已包含便携版、文件夹版构建和原子归档；正式发布不再预先重复运行 `build-portable.cmd`，同一版本禁止并行执行发布脚本。

## 记忆与任务规划（2026-08-06）

- 新任务只固定读取当前状态与交接，再按任务检索相关决策、经验和已知问题，避免历史增长后每次全量通读。
- 任务内过程和临时计划不进入长期记忆；`SESSION_HANDOFF.md` 只保留未完成动作和下一门禁。每项事实只有一个主要归属，详细写入规则以 `memory/README.md` 为准。

## 前端维护方式（2026-08-23）

- 继续使用原生 JavaScript，不迁移到 React/Vue，也不重写界面。源码按工程状态、规则、显示、导入导出和事件拆分在 `web/app/`，构建时由 `web/app-bundle.js` 合成同一作用域，最终仍交付单文件离线 HTML。
- `web/template.html` 只保留页面与唯一程序标记，不保存废弃应用副本；`web/build.js` 必须通过该唯一标记插入程序，并安全处理内联数据。
- 芯片运行配置集中在 `web/device-catalog.js`，但官方封装、默认脚和外设事实继续由 `web/data-validation.js` 独立检查，不能让运行清单自证正确。
- 板卡校验分为所有板卡共用的结构/引用检查与具体板卡事实检查；新增板卡不得要求修改天猛星专用契约。
- 纯内部整理不提升应用版本或存储版本；兼容约定、页面 ID、Electron 桥接和单 HTML 交付保持不变。

## 工程目标与数据兼容（2026-07-14，2026-08-23 更新）

- 保持 Electron `appId`、应用名称和 `app://mspm0/` 稳定。
- 每个工程只对应一个芯片型号和一个封装，在新建工程时固定；顶部不再提供切换入口，型号和封装以中间芯片图为准。
- 空白工程由用户选择型号和封装；开发板模板自动固定对应目标。首次启动没有工程时必须先完成新建工程。
- workspace v7/project data v6 使用单目标结构。软件尚未投入使用，本次结构重做不读取或迁移旧预发布本地存储与 JSON，也不主动删除旧存储键。
- 新默认值只能写入真正的新工程；加载、导入、复制和清空不能补回默认值。

## 官方芯片数据（2026-07-19）

- MSPM0G3507 和 MSPM0G3519 的官方功能分别维护；物理脚相同不代表可跨芯片复制 IOMUX。
- 同一芯片的 RGZ-48 与 PT-48 经官方表确认物理脚号和逻辑引脚一一对应，可以复用并由自动校验保持一致。
- 两颗芯片的 RHB-32 只复用物理脚骨架，完整功能必须回查同一芯片数据。
- VQFN 裸露散热焊盘没有独立规划脚号，不计作第 33 或第 49 个引脚。

## 新工程官方默认接口（2026-07-19）

- 全新工程按对应芯片和封装查找并默认安排 `SWDIO`、`SWCLK`、`NRST`；已有工程、旧导入和清空操作不自动补回。
- 默认项可修改。只有官方数据含 `WAKE` 的 MSPM0G3519 提供 NRST/WAKE 切换，不能为统一界面给 MSPM0G3507 增加不存在的功能。
- Debug、System、Power 使用不同功能颜色；电源/地固定不可编辑。

## 板卡模板（2026-08-06）

- 板级走线保存在 `web/board-presets.json`，与芯片官方引脚数据、用户备注分层。
- 两颗芯片的天猛星 PM-64 模板共用同一 PCB 走线，但默认功能分别由各自官方数据校验。
- 只有用户明确从模板新建时才写入 `boardPresetId` 和板载默认功能；板载安排可修改，冲突只提醒不阻止。
- 功能颜色仍表达官方功能类别。`B/H/!/×/P` 角标只表达物理板卡状态；任一可切换资源启用后，相关引脚统一使用金色高亮边框和 `✓` 角标，关闭后恢复其物理状态角标。
- 一对多板载连接使用 `resources`，共享总线使用 `sharedBuses`。SPI Flash 与外接 H8 LCD/OLED 共用 PB8/PB9，分别使用 PB6/PB14 片选，不属于重复功能冲突。
- 板卡资源控制集中在画布顶部可展开的“板卡资源”栏；Flash 与 LCD 可独立同时启用或同时关闭。资源开关只控制规划占用，不代表断开真实 PCB 连线；新模板当前默认启用 SWD、BSL 与 NRST。
- 启用资源遇到已有用户安排时需确认，确认后完整替换功能、标签、端子和备注；共享 SPI1 功能相同的 PB8/PB9 不作为冲突。关闭资源只清除仍保持该资源预设功能的功能字段，用户填写的标签、端子和备注继续保留；用户改作其他功能的安排也完整保留。
- 清空当前工程的引脚安排时同时关闭板载资源规划开关，但保留板卡身份、永久硬件说明和引脚状态标注；恢复模板初始配置另行恢复五项固定时钟。
- 天猛星新模板默认启用 SWD、BSL 与 NRST；三者开关只控制规划器占用，不改变板上真实连接。NRST/SWD 是正常下载调试的推荐接口，BSL 默认纳入规划但仍允许关闭。
- 板卡资源控制放在芯片工具栏的同一行，展开内容使用浮层覆盖画布，不改变芯片画布尺寸；八项资源在窄浮层中保持单列排列，避免横向内容被中心区域裁切。

## 外设详情分栏（2026-08-23）

- 左侧外设实例列表只负责查找和选择实例；实例的官方信号、完整性提示与安排入口放在其右侧独立详情栏中，不再插入实例列表顶部。
- 外设详情栏是正常布局列，不使用覆盖芯片的浮层。打开时扩大左侧区域并压缩、临时适配芯片画布，关闭后恢复原画布视图；详情栏开合与临时适配不写入工程数据。

## 界面主题（2026-08-06）

- 应用只维护针对桌面规划优化的夜间主题，不保留日间模式或主题切换入口；打印报告仍用白底。
- 旧工程的 `theme` 字段允许读取但忽略，不因移除纯显示偏好提升存储版本。
