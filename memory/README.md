# 项目长期记忆

memory 只保存跨任务仍会影响判断的信息，不代替源码、Git、正式归档或开发文档。

## 读取路由

每个任务先读：

- `PROJECT_STATE.md`：当前真实版本、支持范围、验证状态和所处门禁。
- `SESSION_HANDOFF.md`：尚未完成的动作和下一步。

再按任务检索，不要求机械通读全部历史：

| 文件 | 何时读取 | 何时写入 |
|---|---|---|
| `DECISIONS.md` | 设计、兼容、产品范围、发布方式发生取舍时 | 形成新的长期约束或替换旧决策时 |
| `LESSONS.md` | 遇到构建、测试、数据或界面故障时 | 根因已确认且预防方法可复用时 |
| `KNOWN_ISSUES.md` | 评估发布风险或用户限制时 | 问题仍未解决；解决后删除并由 Git 保留历史 |
| `SESSION_HANDOFF.md` | 每个任务开始和结束 | 有未完成事项、等待确认或下一门禁时；没有则写“无” |

全面审计、memory 重构或用户明确要求时，再完整阅读全部文件。

## 记录边界

- `PROJECT_STATE.md` 是当前快照，不写演进历史；历史由 Git、`CHANGELOG.md` 和 release notes 保存。
- `SESSION_HANDOFF.md` 只写未完成动作，不重复正式版哈希、旧版本功能清单和已完成测试全文。
- `DECISIONS.md` 解释“长期为什么这样做”；`LESSONS.md` 解释“什么故障会怎样复现和预防”。同一事实只选一个主位置。
- 不要求每个任务修改全部 memory 文件；没有新事实就不改。
- 只写已验证事实，不复制聊天、一次性命令输出、猜测、密钥、令牌或个人数据。
- memory 与实际状态冲突时，以源码和测试、Git 标签、`releases/` 为准，并立即修正当前快照。
